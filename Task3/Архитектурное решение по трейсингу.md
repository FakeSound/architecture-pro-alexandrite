# Архитектурное решение по трейсингу

## Потенциальные проблемные места заказа

- Shop API 
- CRM API
- MES API
- RabbitMQ

### Данные в трейсинге

- trace_id
- service_name (имя сервиса)
- operation_name (что происходит)
- status (статус действия)
- error_message (при наличии)

- order_id
- order_status

## Мотивация

Сейчас невозможно отследить путь заказа в единой системе логирования. Для этого придется пройтись по логам всех сервисов и искать заказы по order_id. Это долго и вряд ли получится собрать полную картину.

Для того, чтобы быстро реагировать на инциденты и понимать, в каком сервисе возникла ошибка, необходимо внедрить систему трейсинга.

### Метрики

Основная метрика - Время восстановления после инцидента (MTTR), она будет влиять на кол-во повторных обращений в поддержкку, и на кол-во заказов, которые не были вовремя доставлены, а так же на удовлетворенность клиентов.

А вот какие еще могут быть, на которые влияет именно трейсинг я не понял. Тк остальные метрики можно отследить через уже существующие инструменты системы.


## Предлагаемое решение

Внедряем:
- OpenTelemetry
- Jaeger и JaegerUI

Обновляем сервисы для поддержки трейсинга:
- Shop API
- CRM API
- MES API

Ссылка на схему: [OpenTelemetry + Jaeger Architecture](jewerly_c4_model_tracing.drawio.png)

## Компромиссы

С учетом того, что MES был написан вне компании, есть вероятность, что в нем придется разбираться. Что может затянуть сроки и соответственно финансовую нагрузку на внедрение трейсинга.

Вместо OpenTelemetry можно использовать подход correlation ID. Генерировать trace_id на входе в API и прокидывать его через всю систему и использовать в логах. Это проще и дешевле, но менее функционально.

Трейсинг внедряется только на работу с заказом, никаких других бизнес-процессов он не затрагивает, чтобы упростить внедрение и поддержку.

## Безопасность

### Jaeger UI

- Развёрнут во внутренней сети, без публичного IP
- Доступ снаружи только через VPN
- Доступ только для членов команды разработки

### OpenTelemetry Collector

- Принимает span-ы только от доверенных сервисов внутри сети
- Недоступен извне

### Данные в трейсах

- В span-атрибуты не попадают персональные данные клиентов, данные оплаты и содержимое 3D-файлов — только технические идентификаторы
